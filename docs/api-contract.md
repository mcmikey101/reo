# Контракт API для фронтенда

Контракт `api` (`be/`) для фронтенда: общие правила и эндпоинты. На E0 описаны точки (экран M1). Контракты остальных экранов добавляются сюда первой задачей своего эпика.

Пока API не реализован, источник правды — этот документ, по нему делаются моки MSW. После реализации прав OpenAPI бэкенда (`/docs`, `/openapi.json`), а здесь остаются смысл полей и примеры. Изменения — через PR с пометкой для фронтенда (Георгий) и бэкенда (Сергей).

Актуально на 10.11.2026. Поля и лимиты — по [db-schema.md](db-schema.md), поведение экранов — по [screens.md](screens.md).

---

## 1. Общие правила

### 1.1. Адрес и формат

| Что | Правило |
|---|---|
| Базовый адрес | `VITE_API_URL`, локально `http://localhost:8000` ([conventions.md](conventions.md)) |
| Пути | Без префикса версии: `/points`, `/points/{id}` |
| Формат | JSON в UTF-8: `Content-Type: application/json` в запросах с телом и в ответах |
| Имена полей | `snake_case` |
| Идентификаторы | `id` — UUID строкой: `"3f2b9c1e-8a4d-4c6b-9f1a-2d7e5b8c0a11"` |
| Пустые значения | Отсутствующее необязательное значение — `null`, а не пустая строка и не отсутствие поля в ответе |

### 1.2. Организация и доступ

- `organization_id` в запросах не передаётся и в ответах не возвращается. Бэкенд берёт организацию у текущего пользователя (до E10 его подставляет заглушка, REO-27).
- Запись другой организации для API не существует: ответ `404 not_found`, как и для несуществующей записи.
- `401` зарезервирован под вход в E10. До этого его не бывает.

### 1.3. Строки

- Пробелы по краям обрезаются, лимиты длины считаются после обрезки.
- Обязательное поле, пустое после обрезки, даёт ошибку `blank`.
- Необязательное поле, пустое после обрезки, сохраняется как `null`.

Лимиты полей совпадают с формами на экранах. Фронт проверяет их сам (Zod), а бэкенд проверяет ещё раз.

### 1.4. Дата и время

| Что | Формат | Пример |
|---|---|---|
| Момент времени (`created_at`, `updated_at` и т. п.) | ISO 8601 в UTC с суффиксом `Z` | `"2026-11-10T09:15:00Z"` |
| Дата без времени (границы периода — с E4) | `YYYY-MM-DD`, день по Europe/Moscow | `"2026-11-10"` |

Фронт показывает время в Europe/Moscow ([data-rules.md](data-rules.md#1-выборка-и-период)). Бэкенд хранит его в UTC.

### 1.5. Ошибки

Все ответы 4xx и 5xx имеют одно тело:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Проверьте поля формы",
    "details": {
      "fields": [
        {"field": "name", "code": "too_long", "message": "Не больше 120 символов"}
      ]
    }
  }
}
```

| Поле | Что это |
|---|---|
| `code` | Машинный код ошибки, по нему фронт выбирает поведение |
| `message` | Текст по-русски, его можно показать пользователю |
| `details` | Объект с подробностями, его состав зависит от `code`. Если подробностей нет — `null` |

Коды ошибок:

| HTTP | `code` | Когда | `details` |
|---|---|---|---|
| 404 | `not_found` | Записи нет или она принадлежит другой организации | `null` |
| 409 | `possible_duplicate` | Совпали название и адрес с другой точкой (см. [2.4](#24-post-points--создать-точку)) | `existing_point` |
| 422 | `validation_error` | Неверное тело, параметры запроса или путь | `fields` |
| 500 | `internal_error` | Непредвиденная ошибка сервера | `null` |

Коды полей в `details.fields[].code`:

| `code` | Когда |
|---|---|
| `required` | Обязательное поле не передано или равно `null` |
| `blank` | Обязательное поле пустое после обрезки пробелов |
| `too_long` | Превышен лимит длины |
| `invalid_type` | Неверный тип: число вместо строки, не UUID и т. п. |
| `invalid_value` | Значение вне допустимых: `limit` вне диапазона, неизвестный `sort` |
| `unknown_field` | В теле есть поле, которого нет в контракте. Так ловятся опечатки |

`field` — имя поля тела, параметра запроса (`limit`, `sort`) или пути (`id`).

Бэкенду: FastAPI по умолчанию отвечает `{"detail": ...}`, поэтому нужны свои обработчики `RequestValidationError`, `HTTPException` и необработанных исключений, которые возвращают этот формат.

### 1.6. Пагинация

Списки пагинируются через `limit` и `offset`.

| Параметр | Тип | По умолчанию | Ограничения |
|---|---|---|---|
| `limit` | int | 50 | 1–200 |
| `offset` | int | 0 | ≥ 0 |

Ответ списка:

```json
{"items": [], "total": 0, "limit": 50, "offset": 0}
```

`total` — число записей с учётом фильтров, без учёта `limit` и `offset`. `offset` за пределами `total` — не ошибка, а пустой `items`.

### 1.7. Сортировка

Параметр `sort` — имя поля, `-` перед ним означает обратный порядок: `sort=-created_at`. Допустимые поля указаны у каждого эндпоинта, остальные дают `422 invalid_value`. При равных значениях записи дополнительно сортируются по `id`, поэтому порядок между страницами стабилен.

## 2. Точки

Точка — филиал организации (экран M1). Таблица — `points` ([db-schema.md](db-schema.md#points--точка)).

| Метод и путь | Что делает | Успех | Ошибки |
|---|---|---|---|
| `GET /points` | Список точек с поиском и пагинацией | 200 | 422 |
| `GET /points/{id}` | Одна точка | 200 | 404, 422 |
| `POST /points` | Создать точку | 201 | 409, 422 |
| `PATCH /points/{id}` | Изменить часть полей | 200 | 404, 409, 422 |
| `DELETE /points/{id}` | Удалить точку вместе с её источниками и отзывами | 204 | 404, 422 |

### 2.1. Объект `Point`

```json
{
  "id": "3f2b9c1e-8a4d-4c6b-9f1a-2d7e5b8c0a11",
  "name": "Кофейня на Тверской",
  "address": "Москва, ул. Тверская, 1",
  "category": "кофейня",
  "sources_count": 0,
  "data_status": "no_sources",
  "created_at": "2026-11-10T09:15:00Z",
  "updated_at": "2026-11-10T09:15:00Z"
}
```

| Поле | Тип | `null` | Что это |
|---|---|---|---|
| `id` | string (UUID) | нет | Идентификатор |
| `name` | string, 1–120 | нет | Название |
| `address` | string, 1–250 | нет | Адрес |
| `category` | string, 1–60 | да | Категория, по ней фильтрует выборка (S1) |
| `sources_count` | int ≥ 0 | нет | Число подключённых источников — колонка «Подключения» в M1 |
| `data_status` | enum | нет | Сводный статус данных точки (ниже) |
| `created_at` | string (дата-время) | нет | Когда создана |
| `updated_at` | string (дата-время) | нет | Когда изменена в последний раз |

**`data_status`** сводит статусы источников точки ([data-rules.md](data-rules.md#7-источники-и-статусы)):

| Значение | Подпись в интерфейсе | Когда |
|---|---|---|
| `no_sources` | Нет источников | `sources_count = 0` |
| `collecting` | Идёт сбор | Хотя бы один источник проверяется или собирается, ошибок нет |
| `ok` | Актуально | Все активные источники работают |
| `error` | Ошибка | Хотя бы один источник с ошибкой |
| `paused` | Приостановлено | Все источники приостановлены |

Пока нет источников (до E2), бэкенд всегда отдаёт `sources_count: 0` и `data_status: "no_sources"`. Набор значений фиксирован, а правило свёртки в столбце «Когда» предварительное: его уточняет Михаил вместе с таблицами источников (E2). Если появится новое значение, фронт показывает его как «—», а не падает.

### 2.2. `GET /points` — список точек

Параметры запроса:

| Параметр | Тип | По умолчанию | Что делает |
|---|---|---|---|
| `q` | string, до 100 | — | Поиск подстроки без учёта регистра в `name` или `address`. Пустая строка — без поиска |
| `sort` | string | `name` | `name`, `-name`, `created_at`, `-created_at` |
| `limit`, `offset` | int | 50, 0 | [1.6](#16-пагинация) |

Ответ `200`:

```json
{
  "items": [
    {
      "id": "3f2b9c1e-8a4d-4c6b-9f1a-2d7e5b8c0a11",
      "name": "Кофейня на Тверской",
      "address": "Москва, ул. Тверская, 1",
      "category": "кофейня",
      "sources_count": 0,
      "data_status": "no_sources",
      "created_at": "2026-11-10T09:15:00Z",
      "updated_at": "2026-11-10T09:15:00Z"
    },
    {
      "id": "a7c4e2d0-5b1f-4e8a-b3c9-6f0d2e4a8b17",
      "name": "Кофейня на Арбате",
      "address": "Москва, ул. Арбат, 24",
      "category": null,
      "sources_count": 0,
      "data_status": "no_sources",
      "created_at": "2026-11-10T09:20:00Z",
      "updated_at": "2026-11-10T10:05:00Z"
    }
  ],
  "total": 2,
  "limit": 50,
  "offset": 0
}
```

Пустой список — не ошибка: `{"items": [], "total": 0, "limit": 50, "offset": 0}`. Без `q` это состояние «Добавьте первую точку», с `q` — «поиск ничего не нашёл».

### 2.3. `GET /points/{id}` — одна точка

Ответ `200` — объект `Point` ([2.1](#21-объект-point)). Если точки нет или она чужая — `404 not_found`. Если `id` не UUID — `422`, `field: "id"`, `code: "invalid_type"`.

### 2.4. `POST /points` — создать точку

Тело:

| Поле | Тип | Обязательно | Правило |
|---|---|---|---|
| `name` | string | да | 1–120 после обрезки |
| `address` | string | да | 1–250 после обрезки |
| `category` | string \| null | нет | До 60. Пустое или `null` → `null` |

```json
{"name": "Кофейня на Тверской", "address": "Москва, ул. Тверская, 1", "category": "кофейня"}
```

Ответ `201` — созданный объект `Point`.

**Возможный дубль.** Одинаковый адрес допустим. Если же у другой точки организации совпадают и `name`, и `address`, бэкенд не создаёт точку, а отвечает `409 possible_duplicate`. Сравнение идёт без учёта регистра, после обрезки пробелов по краям и замены нескольких пробелов подряд одним.

```json
{
  "error": {
    "code": "possible_duplicate",
    "message": "Точка с таким названием и адресом уже есть",
    "details": {
      "existing_point": {
        "id": "3f2b9c1e-8a4d-4c6b-9f1a-2d7e5b8c0a11",
        "name": "Кофейня на Тверской",
        "address": "Москва, ул. Тверская, 1"
      }
    }
  }
}
```

Фронт показывает предупреждение о возможном дубле. Если пользователь подтвердит, тот же запрос повторяется с параметром `allow_duplicate=true` (`POST /points?allow_duplicate=true`): проверка дубля пропускается, ответ `201`.

### 2.5. `PATCH /points/{id}` — изменить точку

Передаётся любое подмножество полей из [2.4](#24-post-points--создать-точку), с теми же правилами:

- поле не передано — не меняется;
- `category: null` или `""` очищает категорию;
- `name: null` или `address: null` → `422`, `code: "required"`;
- пустое тело `{}` → `200`, точка не меняется.

```json
{"address": "Москва, ул. Тверская, 3", "category": null}
```

Ответ `200` — обновлённый объект `Point`:

```json
{
  "id": "3f2b9c1e-8a4d-4c6b-9f1a-2d7e5b8c0a11",
  "name": "Кофейня на Тверской",
  "address": "Москва, ул. Тверская, 3",
  "category": null,
  "sources_count": 0,
  "data_status": "no_sources",
  "created_at": "2026-11-10T09:15:00Z",
  "updated_at": "2026-11-10T11:40:00Z"
}
```

Дубль проверяется так же, как при создании: итоговая пара (`name`, `address`) сравнивается с другими точками организации, сама точка не учитывается. При совпадении — `409 possible_duplicate`, после подтверждения — повтор с `allow_duplicate=true`.

### 2.6. `DELETE /points/{id}` — удалить точку

Ответ `204` без тела. Вместе с точкой удаляются её источники и отзывы (`ON DELETE CASCADE`, решение 10.11). Восстановления нет, поэтому в подтверждении фронт называет точку и предупреждает об этом ([screens.md](screens.md#m1-точки)).

- Точки нет или она чужая — `404 not_found`. Повторное удаление тоже даёт `404`, фронт считает его успехом.
- Выборка хранится на фронте, поэтому удалённую точку из неё исключает фронт ([data-rules.md](data-rules.md#1-выборка-и-период)).

## 3. Примеры ошибок для моков

Ответы для фикстур MSW. Успешные ответы — в разделе 2.

**422 — длинное название и пустой адрес** (`POST /points`):

```json
{
  "error": {
    "code": "validation_error",
    "message": "Проверьте поля формы",
    "details": {
      "fields": [
        {"field": "name", "code": "too_long", "message": "Не больше 120 символов"},
        {"field": "address", "code": "blank", "message": "Укажите адрес"}
      ]
    }
  }
}
```

**422 — неверные параметры списка** (`GET /points?limit=500&sort=rating`):

```json
{
  "error": {
    "code": "validation_error",
    "message": "Неверные параметры запроса",
    "details": {
      "fields": [
        {"field": "limit", "code": "invalid_value", "message": "От 1 до 200"},
        {"field": "sort", "code": "invalid_value", "message": "Допустимо: name, -name, created_at, -created_at"}
      ]
    }
  }
}
```

**404** (`GET`, `PATCH`, `DELETE /points/{id}`):

```json
{"error": {"code": "not_found", "message": "Точка не найдена", "details": null}}
```

**500**:

```json
{"error": {"code": "internal_error", "message": "Что-то пошло не так. Повторите позже", "details": null}}
```

При ошибке сохранения форма не очищается, введённые данные остаются ([screens.md](screens.md#m1-точки)).

## 4. Соответствие экрану M1

| Элемент M1 | Что использует |
|---|---|
| Заголовок «Точки» и число объектов | `GET /points` → `total` |
| Поиск по названию и адресу | `GET /points?q=…` |
| Строка: название, адрес | `name`, `address` |
| Строка: число подключений | `sources_count` |
| Строка: статус данных | `data_status` |
| Пустое состояние / поиск без результатов | `total = 0` без `q` / с `q` |
| Форма «Добавить точку» | `POST /points`, лимиты из [2.4](#24-post-points--создать-точку) |
| Форма редактирования | `GET /points/{id}` (или строка списка) → `PATCH /points/{id}` |
| Предупреждение о возможном дубле | `409 possible_duplicate` → повтор с `allow_duplicate=true` |
| Ошибка сохранения | Формат [1.5](#15-ошибки), `details.fields` подсвечивают поля |
| Удаление с подтверждением | `DELETE /points/{id}` |
| После создания — «Подключить источник» | Переход в M2 с `id` новой точки, контракт источников — E2 |

Из старого макета в MVP не входят: теги, ответственный, карта и поиск организации на картах, импорт точек, массовые действия, архивация ([decisions.md](decisions.md#отличия-макета-от-решений)).
