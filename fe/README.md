# fe — фронтенд

Веб-интерфейс reo: React + TypeScript + Vite, Tailwind CSS. Отвечает Георгий Сорокин.

- Порт dev-сервера: 5173.
- Адрес API — из переменной `VITE_API_URL` (по умолчанию `http://localhost:8000`).
- Фронт обращается только к API бэкенда, к ML-сервису — нет.
- Node.js **26** (LTS), версия — в `.nvmrc`. Линтер — **oxlint**.
- Dockerfile фронтенда лежит в этой папке.

Соглашения — в [../docs/conventions.md](../docs/conventions.md), экраны и их состояния — в [../docs/screens.md](../docs/screens.md). Макет — Figma, вариант A «Ясный», десктоп 1440.

## Запуск

```bash
cd fe
npm ci        # зависимости строго по package-lock.json
npm run dev   # http://localhost:5173
```

Индикатор «API · БД · ML» в шапке ходит в API на `http://localhost:8000`. Если бэкенд не запущен, индикатор красный — это ожидаемо.

- **Без бэкенда:** `npm run dev:mock`. Запросы к API перехватывает MSW (`src/mocks`), индикатор зелёный. Красные состояния — параметром в адресе: `http://localhost:5173/dashboard?health=db-error` (ещё `ml-error` и `down`).
- **Другой адрес API:** создайте `fe/.env.local` со строкой `VITE_API_URL=http://…` и перезапустите `npm run dev`. Файл в git не попадает.
- Открывайте именно `http://localhost:5173`: CORS бэкенда разрешает только этот адрес. С `http://127.0.0.1:5173` индикатор будет красным.

### Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Dev-сервер на 5173 |
| `npm run dev:mock` | Dev-сервер с моками API вместо бэкенда |
| `npm run lint` | oxlint; предупреждения тоже считаются ошибками |
| `npm run typecheck` | Проверка типов (`tsc -b`) |
| `npm test` | Тесты Vitest (`npm run test:watch` — в режиме наблюдения) |
| `npm run build` | Проверка типов и сборка в `dist/` |
| `npm run check` | Линтер, тесты и сборка — то же, что в CI |

### CI

Node — из `fe/.nvmrc` (в `actions/setup-node` — параметр `node-version-file`). Затем в папке `fe/`: `npm ci`, `npm run lint`, `npm test`, `npm run build`.

### Docker

```bash
docker build -t reo-fe fe
docker run --rm -p 5173:5173 reo-fe
```

Образ `node:26-slim` запускает dev-сервер Vite, как записано в соглашениях. `VITE_API_URL` — переменная окружения контейнера, по умолчанию `http://localhost:8000`. Адрес открывается в браузере пользователя, поэтому в нём `localhost`, а не имя сервиса `api`.

## Структура

```
fe/
├── src/
│   ├── main.tsx              # точка входа: шрифт, стили, моки, провайдеры, роутер
│   ├── router.tsx            # маршруты: какой экран открывается по какому адресу
│   ├── paths.ts              # адреса экранов
│   ├── pages/                # экраны — по одному на маршрут
│   ├── components/           # общие компоненты: EmptyState, PageHeader, HealthIndicator, кнопки
│   │   └── layout/           # каркас: AppLayout, Header, Sidebar, пункты меню (navigation.ts)
│   ├── api/                  # API-клиент: client.ts, запросы и хуки по разделам API
│   ├── state/                # состояние интерфейса, которое не приходит с сервера
│   ├── mocks/                # моки API на MSW
│   ├── styles/               # index.css: Tailwind и токены макета
│   ├── lib/                  # функции без React: cx, форматирование
│   └── test/                 # настройка Vitest и хелперы рендера
├── public/                   # файлы без обработки: favicon
├── index.html
├── Dockerfile
├── .nvmrc                    # версия Node
├── .oxlintrc.json            # правила линтера
├── vite.config.ts            # Vite: плагины, порт, настройки тестов
└── package.json
```

| Каталог | Что кладём | Чего не кладём |
|---|---|---|
| `pages/` | Экран целиком: `<Экран>Page.tsx`, по одному на маршрут. Экран собирает компоненты и берёт данные из хуков `api/`. Когда у экрана появляются свои части, он переезжает в папку: `pages/points/PointsPage.tsx`, `pages/points/PointForm.tsx` | Компоненты, нужные нескольким экранам |
| `components/` | Компоненты для нескольких экранов: пустое состояние, заголовок экрана, кнопки (`button.ts`), индикатор состояния | Запросы к API и код одного экрана |
| `components/layout/` | Каркас: шапка, боковое меню, общий макет страницы, список пунктов меню | Содержимое экранов |
| `api/` | `client.ts` — запросы и ошибки `ApiError` по общим правилам [api-contract.md](../docs/api-contract.md). На каждый раздел API — файл (`health.ts`, `points.ts`): типы по контракту, функции запросов и хуки TanStack Query (`useHealth`, `usePoints`) | `fetch` прямо в компонентах |
| `state/` | Состояние интерфейса: свёрнутое меню, позже — выборка (точки, источники, период), если её решат хранить на фронте | Данные с сервера: их кеширует TanStack Query |
| `mocks/` | Обработчики MSW по контрактам из `docs/` (`handlers.ts`). `browser.ts` подключается в `npm run dev:mock`, `node.ts` — в тестах | Логику приложения |
| `styles/` | `index.css`: подключение Tailwind и токены макета в `@theme` | Стили отдельных компонентов: они пишутся классами Tailwind в разметке |
| `lib/` | Функции без React: склейка классов, форматирование чисел и дат | Компоненты и хуки |
| `test/` | `setup.ts` (jest-dom, MSW), `render.tsx` (рендер с кешем запросов и роутером) | Сами тесты: они лежат рядом с кодом, `<Файл>.test.tsx` |

### Как добавить экран

1. Адрес — в `src/paths.ts`.
2. Экран — `src/pages/<Экран>Page.tsx`: `PageHeader` и содержимое. Пустое состояние, загрузка и ошибка — по [screens.md](../docs/screens.md).
3. Маршрут — в `src/router.tsx`, в `children` рядом с остальными экранами: тогда он получает шапку, меню и обработку ошибок.
4. Пункт меню, если нужен, — в `src/components/layout/navigation.ts`.
5. Тест рядом с экраном: `<Экран>Page.test.tsx`, рендер через `renderApp('/адрес')` из `src/test/render.tsx`.

### Как добавить запрос к API

1. В `src/api/<раздел>.ts` — тип ответа по [api-contract.md](../docs/api-contract.md), функция запроса через `apiGet` и хук `useQuery`. Для POST, PATCH и DELETE добавьте функции рядом с `apiGet` в `client.ts`.
2. Мок — в `src/mocks/handlers.ts`, по контракту. С ним экран можно делать до готовности бэкенда (`npm run dev:mock`) и тестировать.
3. В экране — хук: `const points = usePoints()`.

## Стили

- Tailwind CSS 4, классы прямо в разметке.
- Цвета, размеры текста, скругления и тени — только токены макета из `src/styles/index.css`: `bg-page`, `bg-surface`, `text-ink-2`, `border-line`, `text-h1`, `text-body`, `rounded-sheet`, `shadow-pop`. Стандартная палитра Tailwind отключена. Новый цвет сначала добавляется в токены, в комментарии — имя переменной Figma.
- Шрифт — Golos Text из пакета `@fontsource-variable/golos-text`, файлы шрифта собираются вместе с приложением.
- Иконки — Lucide (`lucide-react`), как в макете, толщина линии 1.75.
- Размеры каркаса по макету: шапка 56 px, меню 232 px (свёрнутое — 64 px), отступы рабочей области 24 px.

## Индикатор состояния

`src/components/HealthIndicator.tsx` в шапке опрашивает `GET {VITE_API_URL}/health` раз в 15 секунд, пока вкладка открыта. Нажатие — проверить сразу. Формат ответа — [conventions.md](../docs/conventions.md), раздел 7.

| Ситуация | Что видно |
|---|---|
| API ответил, `db` и `ml` = `ok` | API · БД · ML зелёные |
| API ответил, `db` или `ml` = `error` | Красная только эта часть |
| API не отвечает, ответил ошибкой или не по формату | Все три красные: состояние БД и ML неизвестно. Страница работает дальше |

Кроме цвета состояние показывает значок: галочка или крестик. При наведении или фокусе — подсказка: состояние каждой части словами, время проверки и адрес API.

## Отличия от макета

- Название — reo (в макете «Отклик»).
- Пункта «Область анализа» (S1) пока нет: отдельный экран это или панель на дашборде — открытый вопрос ([screens.md](../docs/screens.md)).
- Индикатора состояния в макете нет — он сделан в стиле чипов шапки.
- Вместо названия организации и инициалов в шапке — значок профиля без действий. Меню профиля появится вместе со входом (E10).
- Телефонная версия (нижняя навигация) — не в этой задаче.
