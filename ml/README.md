# ml — ML-сервис

Отдельный сервис на FastAPI (Python 3.11) для всех ML-фич reo.

Отвечают:
- Камиль Рахматуллин — E3 «Анализ удовлетворённости» (ML-1), E8 «Прогноз и тренды» (ML-3);
- Артём Кречетников — E6 «Проблемы клиентов» (ML-4), E7 «Суммаризация» (ML-2).

- Порт: 8001.
- **Без доступа к БД:** бэкенд передаёт тексты и сохраняет результаты; фронт к ML не обращается.
- Контракт «бэкенд ↔ ML» — [docs/ml-contract.md](../docs/ml-contract.md), соглашения — [docs/conventions.md](../docs/conventions.md).
- Зависимости — `requirements.txt`, линтер — ruff (настройки в `pyproject.toml`).

## Текущее состояние (E0)

Сервис отвечает по контракту v0.2 **заглушкой** модели тональности: `model_version = "mock-0.1"`, в `/v1/health` — `"mock": true`.

| Эндпоинт | Что делает |
|---|---|
| `GET /health` | `{"status": "ok"}` — процесс жив; его опрашивает `/health` бэкенда |
| `GET /v1/health` | Готовность и версии моделей |
| `POST /v1/sentiment` | Тональность пачки до 256 отзывов. Правила выбора метода (текст, звёзды, пропуск) настоящие; по тексту заглушка возвращает «мягкие» вероятности по звёздам, без оценки — нейтрально |

## Структура

Корень импортов — папка `ml/`: код импортируется как `api.main`, `sentiment...`, а не `ml.api.main`. Так он одинаково запускается в Docker, локально и в тестах.

```text
ml/
├── api/                  # HTTP-слой: FastAPI-приложение, схемы, обработчики ошибок
│   └── main.py           #   точка входа (uvicorn api.main:app)
├── sentiment/            # [спринт 2] модель тональности: предобработка, загрузка, predict()
├── tsa/                  # [E8] тренд, сезонность, прогноз
├── problems/             # [E6] выделение проблем клиентов
├── summary/              # [E7] суммаризация
├── notebooks/            # [спринт 1+] исследовательские ноутбуки и бейзлайны
├── reports/              # [спринт 1+] отчёты экспериментов: метрики, выводы
├── data/                 # датасеты — НЕ в git, НЕ в образе
├── models/               # веса моделей — НЕ в git, НЕ в образе
├── tests/                # pytest: правила контракта
├── pyproject.toml        # настройки ruff и pytest
├── requirements.txt      # зависимости: рантайм + разработка
├── .dockerignore
└── Dockerfile            # образ сервиса (контекст сборки — ml/)
```

`[…]` — каталога ещё нет, он создаётся вместе с первой задачей, которой нужен.

- `data/`, `models/`, файлы `*.pt`, `*.bin`, `*.safetensors`, `*.onnx` исключены в корневом `.gitignore` и в `.dockerignore`. Откуда сервис берёт веса в контейнере (скачивание при старте или монтирование тома), решается вместе с реальной моделью в спринте 2.
- Ноутбуки и отчёты в образ не попадают.
- Зависимости для обучения и экспериментов (torch, transformers, jupyter и т. п.) не добавляем в `requirements.txt` сервиса, пока они не нужны в рантайме. torch — только CPU-сборкой.

## Как добавить ML-фичу

1. Реализация — в отдельном пакете (`ml/problems/`, `ml/summary/`): модель или алгоритм за простым интерфейсом, без FastAPI внутри.
2. Схемы и маршрут — в `api/`: в `main.py` или в отдельном модуле с `APIRouter`, подключённом в `main.py`. Ошибки — в общем формате контракта.
3. Сначала описать эндпоинт в `docs/ml-contract.md` (раздел 7 — зарезервированные эндпоинты) и согласовать с бэкендом (Михаил).
4. Тесты на правила контракта — в `tests/`.
5. ML-сервис не подключается к БД и не хранит бизнес-результаты: всё нужное приходит в запросе, результат возвращается в ответе.

## Запуск и проверка

Локально, из папки `ml/`:

```bash
python -m venv .venv
.venv/Scripts/activate            # Windows; на Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt

uvicorn api.main:app --reload --port 8001
curl http://localhost:8001/health   # {"status":"ok"}

ruff check . && ruff format --check .
pytest
```

В Docker, из корня репозитория:

```bash
docker build -t reo-ml ml/
docker run --rm -p 8001:8001 reo-ml
```

В общем `docker-compose.yml` сервис называется `ml`, бэкенд обращается к нему по `http://ml:8001` (REO-18).
