# reo

Сервис аналитики отзывов клиентов для бизнесов с несколькими точками — сетей кафе, магазинов, клиник.

reo собирает отзывы всех точек с площадок и из CSV и с помощью ML превращает их в понятные показатели и выводы: насколько довольны клиенты, на что жалуются, как меняется ситуация и чего ждать дальше.

## Возможности MVP

- Точки организации и источники отзывов: сбор с площадок и импорт CSV
- Анализ тональности и индекс удовлетворённости 0–100
- Дашборд с выбором точек, источников и периода
- Автоматическое выделение проблем клиентов
- Суммаризация отзывов с цитатами, выгрузка в PDF
- Тренд, сезонность и прогноз индекса
- Просмотр исходных отзывов
- Выгрузка анализа в XLSX

## Запуск

Нужен Docker с Docker Compose v2. Из корня репозитория:

```bash
docker compose up --build
```

Первая сборка занимает несколько минут. Когда всё поднимется:

| Сервис | Адрес |
|---|---|
| Фронтенд | http://localhost:5173 |
| API, Swagger | http://localhost:8000/docs |
| Проверка API, БД и ML | http://localhost:8000/health → `{"status": "ok", "db": "ok", "ml": "ok"}` |
| ML-сервис | http://localhost:8001/health |
| PostgreSQL | `localhost:5432`, пользователь, пароль и база — `reo` |

- `api` стартует только после того, как PostgreSQL готов принимать подключения (healthcheck сервиса `db`), затем сам применяет миграции и демо-данные.
- Данные БД хранятся в volume `reo_pgdata` и не пропадают при перезапуске.
- Без файла `.env` используются значения по умолчанию. Чтобы их поменять (например, порт БД, если 5432 занят локальным PostgreSQL), скопируйте образец и отредактируйте: `cp .env.example .env`.
- Код в контейнеры копируется при сборке: после изменений перезапустите с `--build`.

Полезные команды:

```bash
docker compose up --build -d    # запустить в фоне
docker compose ps               # состояние сервисов
docker compose logs -f api      # логи одного сервиса
docker compose down             # остановить, данные БД сохраняются
docker compose down -v          # остановить и стереть данные БД
```

Запуск частей по отдельности, без Docker — в README каждой папки: [be](be/README.md), [ml](ml/README.md), [fe](fe/README.md).

## Как работаем

- Модель — GitHub Flow: `main` всегда рабочий, прямой push в `main` запрещён.
- Ветка на задачу: `<fe/be/ml>/REO-<номер>-<коротко>`, например `be/REO-22-csv-upload`.
- Коммиты с ключом задачи: `REO-22: добавить парсинг CSV`.
- PR в `main` с заголовком `REO-<номер>: …`; описание — что сделано и как проверить. Слияние — squash.
- Обычный порядок: автор проверяет код через Claude, тимлид проверяет PR через Claude и вливает.
- **Временное исключение до 11.11 (E0):** автор сам вливает свой PR после самопроверки через Claude и зелёного CI. Пока CI нет — вместо него автор запускает линтер и тесты локально. Тимлид смотрит влитые PR позже. С 11.11 — обычный порядок.
