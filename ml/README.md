# ml — ML-сервис

Отдельный сервис на FastAPI (Python 3.11) для всех ML-фич reo.

Отвечают:
- Камиль Рахматуллин — E3 «Анализ удовлетворённости» (ML-1), E8 «Прогноз и тренды» (ML-3);
- Артём Кречетников — E6 «Проблемы клиентов» (ML-4), E7 «Суммаризация» (ML-2).

- Порт: 8001.
- **Без доступа к БД:** бэкенд передаёт тексты и сохраняет результаты; фронт к ML не обращается.
- Зависимости — `requirements.txt`, линтер — ruff.
- Данные (`ml/data/`) и веса моделей (`ml/models/`, `*.pt`, `*.bin`, `*.safetensors`, `*.onnx`) в git не коммитим.
- Dockerfile ML-сервиса лежит в этой папке.

## Структура

```text
ml/
├── api/main.py             # FastAPI: маршруты, схемы и общая логика API
├── sentiment/              # модель тональности и её предобработка
├── tsa/                    # модели временных рядов и прогнозирования
├── notebooks/              # исследовательские ноутбуки и baseline
├── tests/                  # тесты ML-сервиса
├── utils.py                # общие ML-утилиты
├── requirements.txt        # зависимости сервиса
└── Dockerfile              # образ сервиса (контекст сборки — ml/)
```

## Как добавить ML-фичу

Добавьте реализацию фичи в отдельный пакет, например `ml/problems/` или
`ml/summary/`, а HTTP-схему и маршрут — в `ml/api/main.py` (или отдельный модуль
маршрута, подключённый к FastAPI). Покройте правила контракта тестами в `ml/tests/`
и обновите `docs/ml-contract.md`. Новая фича получает тексты и другие нужные данные
от бэкенда; ML-сервис не подключается к БД и не сохраняет бизнес-результаты.

Соглашения — в [../docs/conventions.md](../docs/conventions.md), контракт «бэкенд ↔ ML» — в `docs/ml-contract.md` (создаётся в задачах E0).
