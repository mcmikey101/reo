# CLAUDE.md — контекст проекта reo

## Продукт

reo — сервис аналитики отзывов клиентов для бизнесов с несколькими точками (сети кафе, магазинов, клиник). Он собирает отзывы всех точек с площадок и из CSV и с помощью ML превращает их в показатели и выводы: индекс удовлетворённости 0–100, проблемы клиентов, суммаризацию с цитатами, тренд и прогноз. Пользователь выбирает точки, источники и период один раз — выборка действует на всех аналитических экранах. Из любого показателя можно перейти к исходным отзывам.

## Текущий этап

**E0 «Инфраструктура и каркас».** Делаем только каркас: структура, Docker, CI, минимальная схема БД (организация, пользователь, точка, расширение pgvector), заглушка текущего пользователя, базовые контракты, `/health`. Фичи продукта не реализуем.

## Стек

- `fe/` — React, TypeScript, Vite.
- `be/` — Python 3.11, FastAPI, SQLAlchemy 2, Alembic; PostgreSQL 16 + pgvector.
- `ml/` — отдельный сервис на FastAPI, Python 3.11.
- Запуск — Docker Compose, CI — GitHub Actions. Линтер Python — ruff, зависимости — `requirements.txt`.

## Принципы

- **ML-сервис без доступа к БД:** бэкенд передаёт тексты и сохраняет результаты; фронт к ML не обращается.
- Все запросы бэкенда фильтруются по организации текущего пользователя.
- Работай в своей папке. Схему БД и контракты (`docs/db-schema.md`, `docs/api-contract.md`, `docs/ml-contract.md`) меняем только через PR с пометкой для затронутых участников.
- Не коммитить `.env`, ключи и токены, данные и веса моделей.

## Git

- Ветка на задачу: `<fe/be/ml>/REO-<номер>-<коротко>`, от свежего `main`.
- Коммит: `REO-<номер>: <что сделано>`.
- PR в `main`, заголовок `REO-<номер>: …`, описание — что сделано и как проверить. Слияние — squash. Прямой push в `main` запрещён.
