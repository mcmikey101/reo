# reo — инструкции для работы с репозиторием

## Проект

reo собирает отзывы по точкам организации и помогает анализировать тональность, удовлетворённость и жалобы клиентов. Границы MVP описаны в [docs/product.md](docs/product.md), принятые решения — в [docs/decisions.md](docs/decisions.md). Объём конкретного изменения сверяй с задачей REO в Jira.

## Устройство и контракты

- `fe/` — React, TypeScript, Vite. Фронтенд обращается к API бэкенда.
- `be/` — FastAPI, Python 3.11, SQLAlchemy, Alembic, PostgreSQL и pgvector. Все операции с данными ограничены организацией текущего пользователя.
- `ml/` — отдельный FastAPI-сервис на Python 3.11 без доступа к БД. Бэкенд передаёт отзывы в ML и сохраняет результаты.
- Порты, переменные окружения и запуск описаны в [docs/conventions.md](docs/conventions.md) и [README.md](README.md).
- Работай в папке своей части проекта. Перед изменением взаимодействия сервисов сверяйся с [API для фронтенда](docs/api-contract.md), [контрактом ML](docs/ml-contract.md) и [схемой БД](docs/db-schema.md). При изменении контракта или схемы обнови соответствующий документ в PR и отметь затронутых участников.

## Проверки и Git

- Для `be/` и `ml/` запускай `ruff check .`, `ruff format --check .` и `pytest` из изменённой папки. Для тестов бэкенда с БД см. [be/README.md](be/README.md).
- Для `fe/` запускай `npm run check` из `fe/`. Эта команда запускает линтер, тесты и сборку. Сквозной запуск из корня — `docker compose up --build`.
- Ветка на задачу — `<fe/be/ml>/REO-<номер>-<краткое-описание>` от свежего `main`. Ключ задачи указывай в коммите и заголовке PR. В описании PR укажи, что изменилось и как проверить.
- Изменения попадают в `main` через PR. Тимлид вливает PR через squash после ревью и зелёного CI.
- Храни `.env`, ключи, токены, датасеты и веса моделей вне Git. Документацию, коммиты и PR пиши по-русски.
