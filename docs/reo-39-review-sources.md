Исследование от 23.11.2026. Сравнили Яндекс Карты, 2ГИС и Google Maps по доступу к отзывам одной точки, глубине истории, пригодности данных для reo и наличию готовых парсеров.

Оценки без текста могут влиять на рейтинг карточки без публикации отдельной записи. Встроенный браузер получил тайм-аут при проверке живой ленты. [Карточка точки](https://2gis.ru/moscow/firm/4504128908445240/tab/reviews) · [Справка об оценках](https://help.2gis.ru/question/stars)

## 3. Итоговый выбор площадки

**2ГИС — первая площадка для пилота интеграции в MVP.** Через партнёра можно проверить список отзывов конкретной подключённой точки, включая даты и внешние ID. Включение в MVP зависит от условий использования и успешной проверки на реальной точке. Возможность подключения произвольной карточки только по ссылке пока не подтверждена. [API RocketData](https://api.rocketdata.io/public/swagger-ui/) · [Поддерживаемые источники](https://rocketdata.ru/blog/obnovleniya-rd-sent-okt)

**Яндекс Карты — запасной вариант для прототипа по ссылке**, если условия разрешают сбор. У подходящего Python-инструмента уже есть выгрузка с датами, а в публичной карточке видна история нужной длины. **Google Maps откладываем** из-за глубины Places API и ограничений на хранение. [Парсер Яндекс Карт](https://github.com/KrivchenkoEgor/yandex-maps-reviews-scraper) · [Карточка Яндекс Карт](https://yandex.com/maps/org/akademiya_kofe/106159432918/reviews/) · [Ограничения Google](https://developers.google.com/my-business/content/policies#content-storage)

## 5. Итоговый выбор реализации парсинга или готового инструмента

**Для первого пилота — RocketData API и небольшой клиент в бэкенде reo.** `GET /public/v4/reviews/` поддерживает фильтры `company_ids`, `catalog_ids`, `date_gte`, `date_lte` и курсор. Документированный ответ `200` содержит `results`, `next`, `previous` и `per_page`. Проверочный запрос в Swagger с параметрами примера без токена вернул `401` и `WWW-Authenticate: Token`. Авторизованную выдачу ещё предстоит проверить. Указанные для `updated_at_gte` 90 дней описывают срок хранения журнала изменений. Глубину первичной выгрузки измеряем в пилоте. При доступном каталоге Яндекс Карт этот же клиент можно проверить на второй площадке. [Swagger RocketData](https://api.rocketdata.io/public/swagger-ui/) · [Условия RocketData](https://rocketdata.ru/terms_of_use) · [Поддерживаемые источники](https://rocketdata.ru/blog/obnovleniya-rd-sent-okt)

**Если понадобится прототип веб-парсинга — `KrivchenkoEgor/yandex-maps-reviews-scraper`.** Из рассмотренных инструментов у него самый короткий путь от ссылки до полей для reo. Достаточно проверить фактическую выгрузку одной точки, формат дат и повторяемость `reviewId`, затем отобрать колонки для CSV. [Репозиторий парсера](https://github.com/KrivchenkoEgor/yandex-maps-reviews-scraper)

## 6. Соответствие требованиям проекта

Поля нужно сверить на авторизованном образце. Таблица описывает преобразования для путей, в которых есть отдельные записи отзывов. [Схема `sources` и `reviews`](db-schema.md#sources--источник-отзывов)

| Поле reo | Яндекс Карты, парсер | 2ГИС, RocketData | Google, Business Profile / Places |
|---|---|---|---|
| `sources.url`, `source_id` | Карточка одной организации и её ID. | `location_url` и проверенная пара `company.id` / `catalog_id`. | Подтверждённый `locationId` / `placeId` и URL карточки. |
| `date` | Абсолютная дата публикации из результата парсера. Строку без надёжно определяемого года отклонить. | `created_in_catalog`. | `createTime` / `publishTime`. |
| `text` | Полный текст отзыва. | `comment`. | `comment` / `originalText.text` с запасным `text.text`. |
| `rating` | Оценка отдельного отзыва. | `rating`. | `starRating` (`ONE`–`FIVE` → `1`–`5`, `STAR_RATING_UNSPECIFIED` → `null`) / числовой `rating`. |
| `external_id`, `url` | `reviewId` и прямая ссылка, если получена. | `origin_id` и `origin_url`, если получены. | `reviewId` / `name` ресурса. Для Places есть `googleMapsUri`. В схеме Business Profile отдельное поле ссылки на отзыв не заявлено. |

Источники полей — [парсер Яндекс Карт](https://github.com/KrivchenkoEgor/yandex-maps-reviews-scraper) · [Swagger RocketData](https://api.rocketdata.io/public/swagger-ui/) · [ресурс Business Profile](https://developers.google.com/my-business/reference/rest/v4/accounts.locations.reviews) · [ресурс Places](https://developers.google.com/maps/documentation/places/web-service/reference/rest/v1/places#Review).

1. Связать отзыв с `sources.kind = parser` для точки текущей организации. Для автоматического сбора `reviews.import_id = null`. При выгрузке через агрегатор проверять точку и каталог каждой записи.
2. Привести время публикации к календарному дню `Europe/Moscow`. Для даты без времени и часового пояса проверить, какой календарный день описывает поставщик. Убрать крайние пробелы и привести переводы строк в тексте к LF. Пустые значения хранить как `null`. Допустимы оценки 1–5 и запись с текстом либо оценкой. Записи с некорректной датой или значением оценки отклонять.
3. Сохранить стабильный ID площадки и точную ссылку на отзыв при наличии. Вычислить SHA-256 от `["external_id", external_id]` или от `[date, text, rating]` в принятом JSON-формате. Уникальность `(source_id, dedup_key)` действует внутри источника. Автор, контакты, фото и ответы бизнеса в эту схему не входят. [Правила дедупликации](db-schema.md#reviews--общая-таблица-отзывов-csv-и-парсера)
4. Для ручной выгрузки отфильтровать одну точку и один каталог, сформировать UTF-8 CSV с заголовком `date,text,rating`. В текущем импорте текст обязателен. Внешние ID и ссылки CSV не принимает. [Правила CSV](data-rules.md#импорт-csv)

Синтетическая строка для проверки формата. Время публикации `2026-11-21T22:40:00Z` превращается в `2026-11-22` по Москве.

```csv
date,text,rating
2026-11-22,"Кофе понравился, заказ выдали быстро",5
```

Пример принят парсером reo. Целевой набор из 35 тестов CSV прошёл. Открытый датасет Яндекса содержит рейтинг, текст, название и адрес организации, но даты отдельных отзывов отсутствуют. Для CSV reo нужен источник дат. [Датасет и лицензия](https://github.com/yandex/geo-reviews-dataset-2023)

## 7. Итоговые выводы и предложения по интеграции в reo

**На прогоне 24.11 используем существующий CSV-импорт.** Для автоматического сбора сначала проверяем **2ГИС через RocketData**. План реализации зависит от результатов пилота.

1. **Проверить доступ и покрытие одной точки.** Согласовать хранение, анализ и показ отзывов. Запросить одну точку и один каталог, пройти страницы до конца, записать количество уникальных отзывов, диапазон дат, пропуски полей и ограничения API. Если есть сопоставимый счётчик отзывов по тому же каталогу, сверить с ним количество записей. Для годовой сезонности reo нужно от двух лет истории. [Правила прогноза](data-rules.md)
2. **Проверить нормализацию и повторный сбор.** Преобразовать пример ответа в строки `reviews`. Повторить запрос для той же точки и убедиться, что ID совпадают и повторное сохранение не создаёт дублей. По образцу решить, как обновлять изменённые и удалённые отзывы.
3. **После успешного пилота реализовать сбор в `be/`.** При подключении сопоставить выбранную точку reo с `company_id` и каталогом 2ГИС. Перед сбором проверять принадлежность источника организации. Фоновая задача читает страницы API, нормализует и сохраняет записи в `reviews`. На старте источник получает `collecting`, после успешного завершения — `ok`, при сбое — `error` и `last_error`. При появлении новых отзывов обновляется `last_collected_at`. Повторный запуск использует уникальность `(source_id, dedup_key)`. [Схема источника](db-schema.md#sources--источник-отзывов) · [Статусы источников](data-rules.md#7-источники-и-статусы)
4. **Передавать новые записи на анализ по существующему контракту ML.** CSV-импорт предоставляет выборку новых отзывов по `import_id`. Для автоматического источника предусмотреть фоновую выборку по `source_id` и наличию результата анализа. [Контракт ML](ml-contract.md#3-тональность-отзывов) · [Код CSV-импорта](../be/app/services/imports.py)

Если доступ, условия использования или глубина истории не подойдут, для MVP остаётся CSV. Следующая проверка по ссылке — Яндекс Карты при согласованных условиях сбора.
