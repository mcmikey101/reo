# Правила данных

Как считаются показатели и что делать с неполными данными. Единые для бэкенда, ML и фронта: если интерфейс и расчёт расходятся, прав этот документ. Изменения — через PR с пометкой для затронутых участников.

Актуально на 10.11.2026. Что не решено — помечено **«Не решено»**.

---

## 1. Выборка и период

- Выборка = точки × источники × период. Общая для дашборда, отзывов, суммаризации и выгрузок. Сохраняется между экранами и после обновления страницы; именованных наборов нет.
- Период включает первый и последний день. Пресеты 7, 30 и 90 дней и произвольный диапазон; по умолчанию — последние 30 дней.
- Часовой пояс — Europe/Moscow, одинаковый для всей организации.
- Шаг времени на графиках — день, неделя, месяц; по умолчанию неделя.
- Точка удаляется целиком (без архивации): вместе с ней удаляются её источники и отзывы. Если удалённая точка была в текущей выборке, она исключается из неё, а при пустой выборке предлагается выбрать другие точки.

## 2. Отзывы

| Поле | Правило |
|---|---|
| Текст | Может отсутствовать |
| Оценка | 1–5 звёзд, может отсутствовать |
| Дата | Обязательна |
| Точка, источник | Обязательны: у каждого отзыва сохраняется связь с точкой и источником |
| Идентификатор на площадке, ссылка на оригинал | Если получены |

- **Дубли.** Повтор одной записи в одном источнике исключается по идентификатору на площадке или по совпадению полей. Повторный импорт той же записи не создаёт дубль. Дубли между площадками не ищем, интерфейс этого не обещает.
- **Отзыв без текста** учитывается в числе отзывов и в рейтинге; в цитатах и суммаризации не участвует (количество исключённых показывается). **Решает Камиль в контракте ML (REO-26):** как определяется его тональность (в его плане — по звёздам). Результат нужно сверить с долями позитива и негатива на дашборде.
- Имена и контакты авторов не храним и не показываем.

## 3. Тональность

Три класса: позитив, негатив, нейтрально. Модель возвращает метку, вероятности классов, `score = p_pos − p_neg` и версию модели. Отзыв без определённой тональности не входит в знаменатель долей; их число показывается отдельно.

## 4. Показатели дашборда

| Показатель | Определение |
|---|---|
| Индекс удовлетворённости | Значение 0–100, показывается вместе с числом отзывов. Одинаков для всей организации, в интерфейсе не настраивается |
| Отзывы | Число уникальных отзывов выбранных точек и источников за период, включая отзывы без текста |
| Доля негатива | Негативные ÷ отзывы с определённой тональностью × 100 % |
| Доля позитива | Позитивные ÷ отзывы с определённой тональностью × 100 % |
| Средний рейтинг | Среднее по доступным оценкам, шкала 1–5; рядом объём этой подвыборки |

- Для отсутствующего значения показываем «—», а не ноль. Ноль — только когда данные есть и их действительно ноль.
- Пока данные не обработаны, ноль не подставляем: показываем статус обработки.
- Малая выборка: если отзывов в точке графика меньше порога (по умолчанию 10, настраивается), точка помечается, значение и объём видны в подсказке.

## 5. Индекс удовлетворённости

**Не решено.** Формулу утверждает Камиль в спринте 1; от неё зависят дашборд и прогноз. Предложение:

```
индекс = 50 × (1 + среднее(p_pos − p_neg))
```

- 0 — все отзывы негативные, 100 — все позитивные, 50 — баланс. С жёсткими метками равен `(позитив + 0,5 × нейтрально) ÷ всего × 100`.
- Предложение по хранению: не готовый индекс, а суммы по (точка, источник, день): число отзывов, сумма score, числа позитивных, нейтральных и негативных. Индекс любой выборки считается сложением, без повторного запуска модели и без «среднего от средних».
- При малом числе отзывов — сглаживание к среднему по организации или пометка «мало данных».
- Открыто: учитывать ли звёзды (например, 0,7 × текст + 0,3 × оценка). Против: в CSV оценки может не быть.

## 6. Прогноз и тренды

- По плану ML и бэкенда прогноз считается по запросу для текущей выборки и кэшируется по её параметрам.
- По плану ML ряд недельный, горизонт прогноза — 4 недели. Как это совмещается с выбранным шагом и коротким периодом — **не решено**, см. [decisions.md](decisions.md).
- Ответ содержит историю с трендом, прогноз с доверительным интервалом, сезонность (если хватает истории) и статус `ok` или `insufficient_data`.
- При короткой истории показываем «Недостаточно данных для прогноза». Для годовой сезонности нужно от двух лет истории.

## 7. Источники и статусы

- Состояния подключения: проверка, сбор, работает, ошибка, приостановлено. Обработка текста имеет отдельный прогресс («Обработано 80 из 120»).
- Ошибка одного источника не блокирует остальные. Успешные данные и последняя успешная суммаризация при ошибке не удаляются.
- Отключение источника не удаляет собранные отзывы.
- На дашборде всегда видны дата обновления данных и объём обработанного.

### Импорт CSV

- UTF-8, до 10 МБ, есть шаблон. Точка выбирается для всего файла.
- Обязательно: дата и текст. Необязательно: рейтинг 1–5, площадка, ссылка на отзыв, ссылка на страницу организации, идентификатор отзыва в источнике.
- Порядок: загрузка → сопоставление колонок → предпросмотр. Предпросмотр показывает число корректных строк и ошибок (дата не распознана, текст пуст, рейтинг вне диапазона) и даёт скачать список ошибок.
- Корректные строки импортируются только после явного подтверждения. Если все строки ошибочны, продолжить нельзя.

## 8. Проблемы клиентов

- Группы находятся автоматически, без ручной настройки; у группы есть название, размер, доля, динамика.
- Эмбеддинги хранятся в PostgreSQL (pgvector). **Не решено:** метод (кластеризация или LLM; Артём и Камиль, спринт 2) и кто записывает векторы (по умолчанию ML возвращает, бэкенд сохраняет — подтвердить в контракте ML-4).
- Открытые вопросы к ML: только негатив или все отзывы; целые отзывы или фрагменты; на всех данных организации или на текущей выборке; как сохранять устойчивость групп во времени; что показывать при малом объёме данных.
- Переименование групп пользователем — вне MVP.

## 9. Суммаризация

- Формируется только по кнопке для текущей выборки; изменение выборки генерацию не запускает.
- Состав: общий вывод 3–5 предложений; «Что нравится» и «На что жалуются» — тезисы, число подтверждающих уникальных отзывов, 1–2 дословные цитаты.
- Каждая цитата дословно присутствует в исходном отзыве (проверка по текстам обязательна); пропорции берутся из анализа, а не генерируются.
- Прежняя успешная выжимка остаётся доступной, пока строится новая; заменяется только после успеха. На выжимке указаны её параметры и дата; при смене выборки — «Выборка изменилась. Обновите суммаризацию».
- Объём входа: сотни отзывов не помещаются в один запрос LLM — обработка по частям или опора на группы проблем.

## 10. Выгрузки

- **XLSX** — текущая выборка, а не вся организация. Числовые таблицы, на которых построены графики: параметры выборки (организация, точки, источники, даты, часовой пояс, время выгрузки и анализа), KPI и динамика, тональность по интервалам, таблица точек, проблемы клиентов. Если анализ устарел — пометка в файле; неполные данные не выдаются за полные.
- **PDF** — именно показанная версия суммаризации с её параметрами и датой: организация, объём выборки, дата формирования, вывод, тезисы, цитаты и ссылки на отзывы (если есть). Светлое оформление для печати.
- Файлы формируются только по запросу. В имени — тип результата и диапазон дат.
