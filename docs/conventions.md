# Соглашения по каркасу reo

Общие договорённости для всех частей проекта. Меняются только через PR с пометкой для затронутых участников.

---

## 1. Структура и ответственные

| Папка / файл | Что внутри | Отвечает |
|---|---|---|
| `fe/` | Фронтенд: React + TypeScript + Vite | Георгий |
| `be/` | Бэкенд API: FastAPI, SQLAlchemy 2, Alembic | Сергей (чтение и выдача данных фронту), Михаил (сбор, импорт, конвейер к ML, инфраструктура) |
| `ml/` | ML-сервис на FastAPI | Камиль (E3, E8), Артём (E6, E7) |
| `docs/` | Соглашения, схема БД, контракты | все |
| `docker-compose.yml` (корень) | Запуск всего проекта | Михаил |

## 2. Сервисы и порты

| Сервис | Порт | Что это |
|---|---|---|
| `db` | 5432 | PostgreSQL 16 + pgvector, образ `pgvector/pgvector:pg16` |
| `api` | 8000 | Бэкенд (`be/`) |
| `ml` | 8001 | ML-сервис (`ml/`) |
| `fe` | 5173 | Фронтенд (`fe/`), dev-сервер Vite |

Внешний порт `db` может конфликтовать с локально установленным PostgreSQL. Проброс портов наружу решается в REO-18.

**Открытый вопрос:** сервисы `worker` и `redis` — фоновые задачи на Celery + Redis или без них. Решает Михаил к спринту 2.

## 3. Переменные окружения

| Переменная | Кто использует | Значение |
|---|---|---|
| `POSTGRES_USER` | `db` | задаётся в REO-18 |
| `POSTGRES_PASSWORD` | `db` | задаётся в REO-18 |
| `POSTGRES_DB` | `db` | задаётся в REO-18 |
| `DATABASE_URL` | `api` | строка подключения к БД (см. ниже) |
| `ML_URL` | `api` | `http://ml:8001` |
| `VITE_API_URL` | `fe` | `http://localhost:8000` |

**Хост в `DATABASE_URL`:**
- внутри Docker Compose — `db` (имя сервиса);
- при локальном запуске `api` вне Docker — `localhost`.

Значения БД и файл `.env.example` добавляются в REO-18. Файл `.env` в git не коммитим.

`VITE_API_URL` указывает на `localhost`, потому что фронт работает в браузере пользователя, а не внутри сети Docker.

## 4. Python

- Версия — **3.11** во всех Python-частях (бэкенд, ML).
- Линтер — **ruff**.
- Зависимости — `requirements.txt` в папке своей части (`be/requirements.txt`, `ml/requirements.txt`).

## 5. Фронтенд

- React + TypeScript + Vite.
- Версию Node и линтер определяет Георгий в PR каркаса фронтенда.

## 6. Docker

- Каждый пишет Dockerfile в своей папке: `fe/Dockerfile`, `be/Dockerfile`, `ml/Dockerfile`.
- `docker-compose.yml` в корне собирает Михаил.

## 7. Проверка здоровья `/health`

`api` — `GET /health`:

```json
{"status": "ok", "db": "ok|error", "ml": "ok|error"}
```

`ml` — `GET /health`:

```json
{"status": "ok"}
```

Ответ `api` используется для индикатора «API · БД · ML» на фронте.

## 8. CORS

`api` разрешает запросы с `http://localhost:5173`.

## 9. Взаимодействие частей

```
fe  ──HTTP──▶  api  ──HTTP──▶  ml
                │
                ▼
                db
```

- Фронт обращается только к `api`.
- **ML-сервис без доступа к БД:** бэкенд передаёт тексты и сохраняет результаты.
- Все запросы `api` фильтруются по организации текущего пользователя (с E0 — заглушка).
